AI-Generated Text Detection

Detects whether an essay was written by a person or generated by an AI model, using TF-IDF features and classical machine learning.

Live demo: https://YOUR-PROJECT.vercel.app Dataset: DAIGT V2 Train Dataset (Kaggle, D. Kłeczek, 2023)

Machine Learning (ML) group mini project, B.Tech CSE (AI & ML), UIT, Karnavati University.

Authors: Ayush Pandey, Rathod Pushparaj Singh, Agrawal Sangam

Summary

Large language models can write fluent essays, so teachers and publishers need a way to tell human writing from machine writing. Plagiarism checkers cannot do this, because AI text is newly generated and does not copy any source.

This project treats the problem as binary text classification (0 = human, 1 = AI). It compares three classical models on a balanced dataset and deploys the best one as a web app.

Features: TF-IDF on words and word pairs (1–2 grams), up to 50,000 features, English stop words removed, sublinear term-frequency scaling.
Models: Logistic Regression, Multinomial Naive Bayes, Linear SVM (with probability calibration).
Data: 44,868 essays in the original file (27,371 human, 17,497 AI). Balanced to 20,000 essays (10,000 per class), split 80:20 into 16,000 training and 4,000 test essays (stratified, seed 42).
Preprocessing: lowercase, remove URLs, digits and punctuation, collapse whitespace. The same function is used for training, testing and the web app.
Results

Test set of 4,000 essays. Best value in each column in bold.

Model	Accuracy	Precision	Recall	F1	ROC-AUC
Majority baseline	0.5000	0.0000	0.0000	0.0000	0.5000
Logistic Regression	0.9875	0.9980	0.9770	0.9874	0.9988
Naive Bayes	0.9765	0.9862	0.9665	0.9763	0.9978
Linear SVM	0.9932	0.9970	0.9895	0.9932	0.9997

The Linear SVM is the model used in the web app. Five-fold cross-validation of Logistic Regression gives a mean F1 of 0.988, which agrees with the test result.

Ablation study (Logistic Regression, F1): full model 0.9874, unigrams only 0.9856, keep stop words 0.9897, no sublinear TF 0.9869, 10,000 features 0.9871, raw counts 0.9899. The differences are small, so the pipeline is not sensitive to these choices.

Charts and tables are in the results/ folder.

Limitations
The scores come from one benchmark. The most influential words partly reflect topics and style of the dataset (for example car and venus on the human side, super and gonna on the AI side), so the model partly learns prompt and source cues. Accuracy on text from other sources or topics can be lower.
Human essays in the dataset are longer on average than AI essays (417.7 vs. 330.0 words), which may help the model slightly.
The model uses word counts, not word order or meaning, so paraphrased AI text may be missed.
The output is a probability estimate, not proof of authorship. Do not use it as the only evidence against a student.

How to run
1. Web app (local)

Needs Python 3 only, no extra packages.

python dev_server.py

Open http://localhost:3000.

2. Streamlit app (local)
cd streamlit_app
pip install -r requirements.txt
python -m streamlit run app.py

svm_model.pkl and tfidf_vectorizer.pkl must be in the same folder as app.py. The saved files were created with scikit-learn 1.7.2, so use that version to avoid warnings.

3. Reproduce the results
Download train_v2_drcat_02.csv from the dataset link above (it is not included in this repository because of its size).
Open notebooks/AI_Text_Detection_ML_executed.ipynb in VS Code, Jupyter or Google Colab and put the CSV in the same folder.
Run all cells. The notebook uses a fixed random seed (42), so the split and the metrics are reproducible. Timing values depend on your computer.
4. Deploy your own copy on Vercel
Fork or upload this repository to your GitHub account.
On vercel.com, choose Add New > Project, select the repository, keep the preset as Other, and click Deploy.
If you retrain the model, run python export_model.py to regenerate api/model.json and push the change.

Reference paper

The idea was inspired by a BERT-based Kaggle study on the LLM – Detect AI Generated Text competition. That study reports 99.64% validation accuracy on a corpus with 1,375 human essays and only 3 AI essays, where a model that always answers "human" scores the same. This project uses a balanced dataset, identical preprocessing for training and testing, and several metrics to avoid that problem.
